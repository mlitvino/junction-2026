# Frontend v3.2 implementation evidence

14 November 2026. All 29 Stitch frames are implemented as states of the shared application, rather than 29 duplicated pages. Supported domains use existing canonical HTTP contracts in connected mode. Missing services have useful local or unavailable experiences, with their limits explained at the relevant decisions. This is a frontend implementation report, not a claim that every backend checklist item is complete.

Early implementation type/selector mistakes were corrected before the final checks.

## Backend work still required

Current HTTP integration details and precise evidence levels are in [INTEGRATION-STATUS.md](INTEGRATION-STATUS.md). Remaining services are server-persisted/streamed AI conversations, safe autonomous tool orchestration, durable restock scheduler/plan CRUD/reservations, global audit, external agent credentials/MCP, positive allergen evidence and authoritative physical conversions, remote recipe updates, comprehensive provenance, and supplier ordering/payment. Server default-deny and tenant authorization remain backend responsibilities.

The UI does not bypass canonical human approval or turn uncertainty into success. Advanced autonomous purchases with unknown supply pause even if an incomplete backend policy returns ALLOW; changing to a human-review policy and preparing a fresh proposal is required. Creation idempotency after a lost proposal POST response would also need a backend request-key contract; current frontend deduplicates in-flight submission, preserves known records, and never guesses a successful order.
