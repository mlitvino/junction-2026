## Evidence labels

- **CONNECTED_TESTED**: exercised against this checkout's actual local HTTP backend with authenticated sessions. This does not imply production readiness or supplier fulfillment.
- **IMPLEMENTED_NOT_TESTED**: actual route integration exists and compiles; its complete live behavior was not exercised.
- **MOCK_ONLY**: isolated browser-local functionality, never authoritative server state.
- **NOT_CONNECTED / BLOCKED_BY_BACKEND**: unavailable capability with an explicit UI explanation.

## Validation and limits

The local connected browser test creates temporary QA organizations/accounts and a canonical recorded order. These remain local test data; no destructive cleanup, supplier order or payment was attempted. It tested independent browser contexts, not fake role synchronization. The fixture suite exercises the full 29-state UI families, both themes, System, 1440/1280/768/390px and zoom. Screenshots are in `frontend-v3.2-screenshots/`.

Initial baseline commands were blocked by an existing pnpm store/install mismatch before project code ran. Restored the existing frozen lockfile installation without changing dependencies. Final command results and frame mapping are in [the implementation report](FRONTEND-UX-IMPLEMENTATION-STATUS.md).

## Required backend coordination

1. Keep canonical purchasing distinct from alternate `orders.ts`/agent lifecycle; reconcile models before sharing IDs or checkout/audit events.
2. Provide a read-only/approval-aware conversational endpoint and agreed structured SSE events, conversation storage and revision linkage. Current `/api/agent/run` can act and is not used as an unrestricted chat endpoint.
3. Durable restock plan CRUD, scheduler, run history and duplicate coverage/reservation across users.
4. Positive allergen/free-from evidence, verified physical unit conversions, comprehensive preference-safe ranking/substitution and deterministic partial fulfillment.
5. Global insert-only audit, actor display names, provenance snapshots and approval expiry/count services.
6. External scoped agent credentials, revocation and MCP; enable/review default-deny and tenant enforcement server-side.
7. Recipe update/version semantics and supported tax/gross totals where needed.
8. Supplier ordering and payment integration, if ever added. Current backend order source explicitly means no supplier dispatch.

No shared-contract edits or dependency additions are required to review this frontend. See [the current handoff](../src/client/workspace/README.md) for DTO ownership, persistence and proposed event reconciliation.
